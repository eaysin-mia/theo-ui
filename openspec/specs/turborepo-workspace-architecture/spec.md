# turborepo-workspace-architecture Specification

## Purpose
Defines the Turborepo monorepo configuration, task pipelines, workspace dependency graph, and local package linking between `apps/web` and `@theo/ui`.

## Requirements

### Requirement: Turborepo Task Pipelines and Caching

The repository root SHALL define a `turbo.json` file configuring task execution dependencies, cached file outputs, and environment variables across workspace applications and packages.

#### Scenario: Running build task across workspaces
- **WHEN** a developer executes `pnpm build` or `turbo build` from the monorepo root
- **THEN** Turbo builds `@theo/ui` first before building `apps/web` based on `^build` task dependencies, caching build outputs in `dist/**` and `.next/**`

#### Scenario: Re-executing cached builds
- **WHEN** `pnpm build` is executed with unchanged source files
- **THEN** Turbo replays previously cached outputs without recompiling packages

### Requirement: Workspace Protocol Linking

Applications within the monorepo SHALL declare workspace package dependencies using the pnpm `workspace:*` protocol to ensure live resolution against local source packages.

#### Scenario: Playground consumer importing local UI package
- **WHEN** `apps/web` declares `"@theo/ui": "workspace:*"` in its `package.json`
- **THEN** the playground application consumes the local `@theo/ui` package and re-renders upon package changes during development

### Requirement: Artifact-First Live Development Loop

The development orchestration SHALL execute package compilation in watch mode (`tsc --watch`) so that consumer applications develop against the exact compiled `dist/` artifacts intended for publishing.

#### Scenario: Real-time playground updates from compiled artifacts
- **WHEN** a developer edits a component in `packages/ui/src/` during `pnpm dev`
- **THEN** `tsc --watch` recompiles the changed file into `packages/ui/dist/` and `apps/web` reloads via Next.js Fast Refresh

### Requirement: Independent Package Verification

Every package and application in the monorepo SHALL expose independent npm scripts for building, linting, formatting, and typechecking.

#### Scenario: Filtering tasks to the UI package
- **WHEN** a developer executes `pnpm --filter @theo/ui typecheck`
- **THEN** TypeScript validation runs strictly on the `@theo/ui` package without invoking typechecks across unrelated monorepo apps

### Requirement: Continuous Integration Verification Pipeline

The repository SHALL maintain an automated GitHub Actions CI workflow (`.github/workflows/ci.yml`) triggered on pushes and pull requests to designated branches (`main`, `build`) that validates linting, source-code formatting, typechecking, builds, and library packaging.

#### Scenario: Running automated CI on pull requests
- **WHEN** a contributor opens a pull request targeting `main` or `build`
- **THEN** GitHub Actions executes the verification suite, passing without false-positive failures on documentation, specification archives, or workspace manifests

#### Scenario: Packaging verification on UI library
- **WHEN** the CI verification pipeline executes package checking
- **THEN** it resolves `@theo/ui` directly via `pnpm --filter @theo/ui run package:check` and verifies that subpaths and types conform to publint standards

### Requirement: Automated Package Release Pipeline

The repository SHALL maintain an automated GitHub Actions release workflow (`.github/workflows/release.yml`) triggered on pushes to `main` that integrates with Changesets to automate package versioning PRs and publication of `@theo/ui` to the configured registry.

#### Scenario: Publishing new package version via Changesets
- **WHEN** a version bump PR generated by Changesets is merged into `main`
- **THEN** the release workflow builds, verifies, and publishes `@theo/ui` to the designated package registry using `GITHUB_TOKEN` permissions

### Requirement: Component Library Testing Pipeline

The repository SHALL provide automated unit and component testing powered by Vitest, React Testing Library, and jsdom, supporting both single-run CI execution (`pnpm test` / `vitest run`) and interactive watch development (`pnpm test:watch`).

#### Scenario: Running component tests across monorepo
- **WHEN** a developer executes `pnpm test` from the monorepo root
- **THEN** Turborepo executes package tests in dependency order and reports test suite results

#### Scenario: Executing isolated component unit tests
- **WHEN** running tests for `@theo/ui` components
- **THEN** Vitest executes co-located test files using jsdom with global DOM polyfills and React cleanup hooks

### Requirement: Test Artifact Isolation and Build Protection

The build pipeline SHALL exclude test files (`*.test.ts`, `*.test.tsx`) and test setup directories from compiled distribution outputs (`dist/`), ensuring zero test code or test types are published to registry consumers.

#### Scenario: Compiling package with co-located tests
- **WHEN** the package build executes `pnpm build` in `@theo/ui`
- **THEN** TypeScript compiles only production source files to `dist/`, omitting `.test.js` and `.test.d.ts` files
